# Светофор НДС — бот для ИП на УСН

## Назначение решения

Бот «Светофор НДС» помогает индивидуальным предпринимателям на УСН отслеживать приближение к лимиту дохода 20 млн ₽, при превышении которого ИП становится плательщиком НДС. Бот показывает наглядный индикатор (зелёный / жёлтый / красный), прогнозирует месяц превышения лимита, помогает выбрать ставку НДС, считает цену с НДС и ведёт календарь налоговых платежей.

## Основной пользовательский сценарий

1. Пользователь запускает бота в MAX командой `/start` или кнопкой «Начать».
2. Бот спрашивает: ИП на УСН? → Совмещаете с патентом?
3. Бот запрашивает доход за 2025 год.
4. Если доход < 20 млн ₽ — бот предлагает отслеживать доходы 2026 года помесячно. Пользователь вносит доход за первый незаполненный месяц.
5. Бот показывает «светофор» — процент использования лимита, остаток до 20 млн ₽, прогноз месяца превышения.
6. При превышении лимита бот предлагает выбрать ставку НДС (5% без вычета или 22% с вычетом).
7. После выбора ставки доступен калькулятор НДС — пользователь вводит цену без НДС, бот считает сумму НДС и итоговую цену.
8. В календаре пользователь видит ближайшие сроки: авансы по УСН, фиксированные взносы, декларации и уплаты по НДС.

### Технологии

### Архитектура

- **Bot.py** — единственный entry point. Содержит FSM-состояния, обработчики `bot_started`, `message_callback`, `message_created`, функции экранов (светофор, календарь, калькулятор НДС, онбординг).
- **services/logic.py** — статические методы для расчёта дат платежей (УСН, фиксированные взносы, НДС), проверки лимита НДС, расчёта цены с НДС.
- **database/** — слой доступа к данным. `models.py` определяет таблицы `user` и `operation`. `queries.py` (AsyncORM) — асинхронные CRUD-методы. `database.py` — настройка async engine и session_factory.
- **core/config.py** — Pydantic Settings, читает `settings.env` и переменные окружения.

## Запуск через Docker

```bash
docker compose up -d --build
```

Эта команда:
- Собирает образ бота из `Dockerfile`
- Поднимает PostgreSQL 16 в отдельном контейнере
- Создаёт Docker-сеть для связи между контейнерами
- Запускает бота с подключением к БД
- Применяет healthcheck для БД (бот ждёт готовности PostgreSQL)

## Внешние сервисы и интеграции

### MAX API (VK Max)

Бот работает через MAX API — платформу чат-ботов VK Max. Для работы необходим:

- **Токен бота** — получается при регистрации бота на [business.max.ru](https://business.max.ru)
- **Long polling** — бот использует long polling, не требует публичного URL или SSL-сертификата

MAX API **невозможно воспроизвести внутри Docker** — это внешний сервис. Для проверки решения необходимо:

1. Зарегистрировать бота на business.max.ru
2. Получить токен
3. Указать токен в `core/settings.env` → `VK_MAX_TOKEN`
4. Запустить бота через `docker compose up -d --build`
5. Открыть чат с ботом в MAX и пройти сценарий

> Контейнеризация не заменяет работающую версию продукта в MAX: чат-бот должен оставаться доступен для прохождения основного пользовательского сценария.

## Описание работы с данными

### Модели БД

**Таблица `user`:**

| Поле | Тип | Описание |
|---|---|---|
| `id` | int (PK) | Внутренний ID |
| `max_id` | str | ID пользователя в MAX |
| `name` | str | Имя пользователя |
| `tax_rate` | int | Ставка НДС (0 / 5 / 22) |

**Таблица `operation`:**

| Поле | Тип | Описание |
|---|---|---|
| `id` | int (PK) | Внутренний ID |
| `user_id` | int (FK → user.id) | Ссылка на пользователя |
| `type` | enum | `income` (доход) или `expenses` (расход) |
| `month` | int | Месяц (1–12) |
| `year` | int | Год (2025, 2026) |
| `cost` | int | Сумма в рублях |

### Логика расчёта лимита НДС

1. Бот суммирует все доходы пользователя за текущий год: `SUM(cost) WHERE type = income AND year = 2026`
2. Считает средний месячный доход: `AVG(cost) WHERE type = income AND year = 2026`
3. Вычисляет процент: `сумма / 20 000 000 × 100`
4. Прогнозирует месяц превышения: `(20 000 000 - сумма) / средний_доход`
5. Цвет светофора: 🟢 < 70%, 🟡 70–90%, 🔴 ≥ 90%

### FSM-состояния

| Состояние | Описание |
|---|---|
| `INCOME_2025` | Пользователь вводит доход за 2025 год |
| `WAIT_INCOME` | Пользователь вводит доход за месяц 2026 |
| `WAIT_WHAT_IF` | Пользователь вводит гипотетическую сумму |
| `WAIT_VAT_PRICE` | Пользователь вводит цену без НДС |
| `MENU` | Главное меню (светофор) |

## Порядок работы с тестовыми данными

1. Запустите решение: `docker compose up -d --build`
2. Откройте чат с ботом в MAX
3. Пройдите онбординг: УСН → нет патента → доход за 2025 = 5 000 000
4. Внесите доход за январь 2026 = 2 000 000
5. Проверьте светофор: должно быть ~35% (🟢)
6. Внесите доходы за февраль–май по 5 000 000 каждый
7. Проверьте светофор: должно быть > 100% (🔴)
8. Выберите ставку НДС (5% или 22%)
9. Откройте калькулятор НДС, введите цену 10 000 — проверьте расчёт

## Известные ограничения

- **Расходы не сохраняются** — в текущей версии сохраняются только доходы. Модель БД поддерживает расходы (`TypeOperation.expenses`), но UI для их ввода не реализован.
- **FSM in-memory** — состояния пользователей хранятся в памяти процесса. При перезапуске бота все FSM-состояния сбрасываются; данные в БД сохраняются.
- **Один пользователь за раз** — при высокой нагрузке in-memory FSM может давать race conditions. Для продакшена рекомендуется Redis.
- **Патент** — доходы по патенту не учитываются в расчёте лимита (по сценарию). Бот предупреждает об этом.
- **Календарь праздников** — библиотека `holidays` использует производственный календарь РФ. При изменении производственного календаря требуется обновление библиотеки.
- **Ставки НДС** — реализованы только 5% и 22%. Ставки 0% и 10% не поддерживаются.
- **Расчёт фиксированных взносов** — использует константу 57 390 ₽ без учёта стажа ИП в течение года.
- **Лимит 2026 года** — бот отслеживает доходы за 2026 календарный год. Переход на следующий год требует обновления константы `YEAR_TRACK`.

## Порядок остановки и повторного запуска решения

### Остановка

```bash
docker compose down
```

Данные БД сохраняются в Docker-томе `pg_data`.

### Повторный запуск

```bash
docker compose up -d --build
```

Бот запустится с сохранёнными данными пользователей.

### Полный сброс (удаление всех данных)

```bash
docker compose down -v
docker compose up -d --build
```

Флаг `-v` удаляет том `pg_data` — все пользователи и операции будут стёрты, БД создастся заново.

### Просмотр логов

```bash
docker compose logs -f bot      # логи бота
docker compose logs -f db        # логи PostgreSQL
```
